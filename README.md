## 概要

本アプリは、医薬品や日用品を扱う倉庫業務を想定して開発した
フリーロケーション対応の在庫管理システムです。

バックエンドは Laravel、
フロントエンドは React（SPA）で構築し、
REST APIを介してデータを連携しています。

主に以下の業務を管理します。

- 商品管理
- 入庫管理
- 出庫管理
- 在庫照会
- 入出庫履歴
- スタッフ管理
- 管理者・スタッフの認証と権限制御

## 開発背景

医薬品卸倉庫では、
商品の種類・ロット・使用期限・数量・保管場所を正確に管理する必要があります。

特に商品の大きさや入庫数量によっては、
同一商品・同一ロットの商品であっても、
1つの棚だけではすべてを保管できない場合があります。

そこで本アプリでは、
商品ごとに棚を固定するのではなく、
入庫時に空いている棚を利用する
**フリーロケーション方式**を採用しました。

同一ロットの商品を複数棚へ分割して保管できる構成とすることで、
倉庫内の空きスペースを活用しながら、
棚単位で在庫数を追跡できるようにしています。

---

## 解決したい課題

- 入庫・出庫時の数量入力ミスを減らす
- 商品・ロット・棚ごとの在庫状況を可視化する
- 倉庫内の空きスペースを効率的に利用する
- 同一ロットの商品を複数棚へ分散して保管する
- 入出庫履歴を残し、在庫変動を追跡できるようにする
- 管理者と現場スタッフの操作範囲を分ける
- 画面表示と在庫処理の責務を分離し、保守しやすい構成にする
- 複数ユーザーによる同時操作時の在庫不整合を防ぐ

## アプリの特徴

### フリーロケーション管理

一般的な固定ロケーション管理とは異なり、入庫時に空いている棚へ商品を配置できる構成です。

例えば、同一ロットの商品を1つの棚に収められない場合は、次のように複数棚へ分割して保管できます。

```text
商品A
└── ロット LOT-20260801
    ├── 棚 A-01：100個
    ├── 棚 A-02：80個
    └── 棚 B-01：50個
```

本アプリでは以下の構成で管理しています。

- 商品：`products`
- ロット：`stock_lots`
- 棚：`locations`
- ロットと棚の中間管理：`stock_lot_locations`

これにより、

- ロット単位での在庫管理
- 同一ロットの複数棚への分割
- 棚ごとの在庫数量管理

を可能にしています。

### 同時入出庫への対策

複数スタッフが同じ在庫や棚を同時に操作した場合の在庫不整合を防ぐため、入庫・出庫処理はDBトランザクション内で実行しています。

また、対象となる在庫・棚に対して `lockForUpdate()` による排他ロックを行い、先行処理の完了後に最新状態を確認して処理する構成としています。

## 技術選定・設計方針

### Laravel + Reactを分離した理由

在庫管理では、商品管理・入出庫・スタッフ管理など複数の画面から共通の在庫データを扱います。

そのため、画面表示と業務ロジックの責務を分離する目的で、フロントエンドをReact、バックエンドをLaravel APIとして構築しました。

React側は以下を主に担当します。

- 画面表示
- ユーザー操作
- フォーム入力
- API通信

Laravel側は以下を担当します。

- 認証
- 権限制御
- バリデーション
- 在庫更新
- 入出庫処理
- DBトランザクション
- 履歴保存

### REST API構成を採用した理由

フロントエンドとバックエンドを独立して開発・公開できるよう、REST APIを介してデータを連携する構成としました。

これにより、React側とLaravel側の責務を分けやすくし、API単位で認証・バリデーション・テストを行えるようにしています。

### Dockerを採用した理由

Laravel、Nginx、MySQL、phpMyAdmin、MailHogを同じ構成で再現できるようDockerを使用しています。

開発環境の差異を減らし、ローカル環境の構築手順を統一しやすくすることを目的としています。

### Railway / Vercelを選定した理由

フロントエンドとバックエンドを分離した構成に合わせて、以下の環境で公開しています。

- Reactフロントエンド：Vercel
- Laravel API / MySQL：Railway

VercelはGitHubと連携したReactアプリのデプロイを行いやすく、RailwayはDocker化したLaravelアプリとMySQLを公開しやすいため選定しました。

今回のポートフォリオでは、インフラ構築そのものよりも、在庫管理ロジック・API設計・Reactとの連携を成果として見せることを優先しています。

## テスト

本アプリではFeature Testを実装し、認証・権限制御・入出庫処理・バリデーション・DB更新・履歴保存を検証しています。

### 認証機能

- 管理者ログイン
- スタッフログイン

### スタッフ管理

- スタッフユーザーはスタッフ管理機能へアクセスできない
- スタッフユーザーはスタッフ登録を実行できない

### 入庫機能

- 未認証ユーザーは入庫できない
- 入庫処理が正常に完了する
- 入庫数量がDBへ保存される
- 入庫履歴が `transactions` テーブルへ保存される
- 入庫数量0はバリデーションエラーになる

### 出庫機能

- 未認証ユーザーは出庫できない
- 出庫処理が正常に完了する
- 出庫後に在庫数量が減少する
- 出庫履歴が `transactions` テーブルへ保存される
- 在庫数を超える出庫は拒否される
- 出庫失敗時に在庫数量が変更されない
- 出庫数量0はバリデーションエラーになる

## 工夫した点

### スタッフログイン・初回PIN変更

管理者がスタッフを登録すると、社員番号と4桁の仮PINを自動生成します。

ローカル環境ではMailHogへ登録完了メールを送信し、画面上の登録完了モーダルにも社員番号と仮PINを表示します。

初回ログイン時は `users.is_pin_changed` を確認します。

未変更の場合はPIN変更画面へ遷移し、変更完了後は、

```text
is_pin_changed = 1
```

へ更新します。

2回目以降は変更後のPINでスタッフ用ダッシュボードへ直接ログインできます。

### 入庫・出庫と在庫管理

入庫・出庫処理と在庫数を連動させ、在庫更新と同時に `transactions` テーブルへ履歴を記録します。

これにより、「誰が・いつ・どの商品を・どれだけ操作したか」を追跡できる構成としています。

### 同時操作による在庫不整合対策

入庫・出庫処理をDBトランザクション内で実行し、対象の棚・在庫に `lockForUpdate()` を適用しています。

複数ユーザーが同じ在庫を同時に操作した場合でも、先行処理の完了後に最新在庫を確認して処理することで、二重出庫や棚の重複利用を防ぐ構成にしています。

### 管理画面UIのコンポーネント分割

スタッフ管理画面では、一覧表示・新規登録・登録結果・詳細表示が1ファイルに集中していたため、責務ごとにReactコンポーネントへ分割しました。

API通信・状態管理は親コンポーネント側へ残し、画面表示部分を子コンポーネント化することで、可読性と保守性を改善しています。

## 苦労した点

### 1. スタッフ認証フロー

**課題**

仮PIN発行・ハッシュ化・初回PIN変更までの認証状態を正しく連携させる必要がありました。

**対応**

`is_pin_changed` により初回ログインかを判定し、PIN変更完了後にスタッフ用ダッシュボードへ遷移する認証フローを整理しました。

### 2. 入庫・出庫と在庫数の整合性

**課題**

入庫・出庫処理と在庫数、履歴データの整合性を保つ必要がありました。

**対応**

DBトランザクション内で在庫更新と履歴保存を行い、さらに排他ロックを追加することで、同時操作時の在庫不整合にも対応しました。

### 3. Laravel APIとReact間のエラー対応

**課題**

認証エラーやバリデーションエラーについて、Laravel側とReact側のどちらに原因があるか切り分ける必要がありました。

**対応**

APIレスポンス・HTTPステータス・ブラウザのNetwork情報を確認しながら、認証・バリデーション処理を段階的に調整しました。

## 今後の改善予定

### 使用期限を利用した出庫制御

現在は、使用期限をロット単位で登録・保持しています。

出庫時は在庫不足を確認したうえで、入庫日の古いロットから順に在庫を減算しています。

今後は以下への活用を予定しています。

- 使用期限の近いロットから優先出庫するFEFO
- 期限切迫在庫のアラート
- 使用期限切れ商品の出庫制御

### スタッフ作業履歴

現在は管理者画面から、スタッフを含む入出庫担当者を確認できます。

今後はスタッフ自身が「自分の入出庫作業履歴」を確認できる機能を追加する予定です。

### SKU管理の拡張

現在は商品ごとにSKUを管理しています。

今後は1商品に対して複数SKUを持てる構成への拡張を検討しています。

### 配送機能

出庫後の配送先店舗への出荷まで管理できるよう、配送機能の拡張を予定しています。

想定機能：

- 配送先店舗の選択
- 商品・数量の指定
- 出荷伝票の発行
- 出荷確定
- 配送ステータス管理

想定テーブル：

| テーブル | 役割 |
|---|---|
| `shipments` | 出荷伝票の基本情報 |
| `shipment_items` | 出荷商品・数量 |
| `transactions` | 在庫変動履歴 |

`shipments` では、

```text
draft
confirmed
shipped
```

などのステータス管理を想定しています。

## 環境構築手順

### 1. リポジトリをクローン

```bash
git clone https://github.com/shoyama1010/drugs-stock-app.git
cd drugs-stock-app
```

### 2. Dockerコンテナを起動

```bash
docker compose up -d --build
```

### 3. PHPコンテナへ入る

```bash
docker compose exec php bash
```

Laravel本体は `/var/www/src` にあります。

```bash
cd /var/www/src
```

### 4. Laravel依存パッケージをインストール

```bash
composer install
```

### 5. `.env` を作成

```bash
cp .env.example .env
```

DB設定例：

```env
DB_CONNECTION=mysql
DB_HOST=mysql
DB_PORT=3306
DB_DATABASE=drugstore
DB_USERNAME=laravel
DB_PASSWORD=secret
```

`docker-compose.yml` のMySQL設定と一致させてください。

### 6. アプリケーションキーを生成

```bash
php artisan key:generate
```

### 7. テーブル・初期データを作成

```bash
php artisan migrate --seed
```

### 8. キャッシュをクリア

```bash
php artisan optimize:clear
```
